# Contracts — typed, versioned sprint & event schemas

Miro Workflows uses **typed, versioned** contracts as the single source of truth
for every cross-package payload:

- The HTTP API request body for `POST /api/runs`.
- The MCP run-emitting tools (future, when we wire 1:1).
- Audit events emitted by every state change.
- Run results returned to callers and dashboards.

Contracts live in **`shared/contracts/`**.

## Files

- `shared/contracts/index.ts` — zod schemas + `parseContract` dispatcher.
- `shared/contracts/json-schema.ts` — hand-rolled JSON-Schema emitter.
- `shared/contracts/sprint.contract.v1.json` — generated by `pnpm run contracts:build`.
- `shared/contracts/audit.contract.v1.json` — generated.

## Version policy

| Action | Required step |
| --- | --- |
| Change a field shape | Bump the version constant (e.g. `1.0.0` → `1.1.0`) and add the new schema to the registry. Keep the old version in the registry for at least one minor release. |
| Remove a field | Add a new major version; old version keeps the field for clients on the old contract. |
| Rename a version constant | Update `pnpm run contracts:check` (it asserts `latest = "x.y.z"`). |

`scripts/check_contract_versions.ts` asserts every registry version is monotonic.

## Adding a new contract

1. Add a file under `shared/contracts/<kind>.contract.v<n>.ts` (or extend
   `index.ts` for small additions).
2. Bump the constant.
3. Add an entry to the relevant `CONTRACTS` registry.
4. Update the parse dispatcher.
5. Add a test to `shared/contracts/contract.test.ts`.
6. Run `pnpm run contracts:build` to refresh the JSON artifacts.

## Errors

`parseContract` throws an `Error` whose message starts with
`Contract <kind> v<n> validation failed`. The HTTP API wraps that in a
`ResponseError(400, …)`. The MCP server returns it as an MCP `isError: true`
result.
